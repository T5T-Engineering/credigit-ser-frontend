# Module documentation index

Project invariant 14: every module in `src/modules/<module>` has `REQUIREMENTS.md` (what the PRD asks for: scope, roles and permissions, rules, workflows, notifications, events/hooks, integrations, open questions) and `IMPLEMENTATION.md` (what the code does: files, routes, data, rule and permission keys, tests, traceability, gaps, tech debt). Update both in the same change as the code.

Sources: PRD (`../README.md` in the workspace root, Appendix A section numbers), `docs/OPEN-QUESTIONS.md`, `TECH-DEBT.md`, `docs/FRONTEND-CONVENTIONS.md`, permission catalogue `credigit-ser-core-backend/src/Host.Credigit.Risk360.Api/config/permissions.json` (`Area` = nav module below).

Status values: **Prototype (demo data)** = complete screens on mock data with the platform services (rules, Operations, notifications, events, hooks, audit) wired in the browser; no backend yet.

Backend counterpart docs live in `credigit-ser-core-backend/docs/modules/<Name>/`.

## Cross-cutting gaps (all modules)

- **Invariant 12:** the UI gates actions by `useCan(module, "view" | "edit")` (role → module map in `src/lib/rbac/roles.ts`), and some modules by role lists or role-id checks. It does not check any named key from the permission catalogue.
- **Invariant 9 (connector-ready):** `docs/integration-points.md` does not exist yet. Integration points are listed only in each module's REQUIREMENTS §8.
- **Invariant 8:** approver roles and SLA hours in the registered default workflow definitions are literals. TD-127 records this for ifrs9 and market-risk; other modules follow the same pattern.
- **Audit immutability:** the audit log is held in browser storage until the backend lands.
- **Tests:** vitest is configured but there are no unit tests. Coverage comes from the Playwright e2e specs only.
